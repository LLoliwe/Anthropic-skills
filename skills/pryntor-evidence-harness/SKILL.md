# Pryntor Agent Integrity

Follow Pryntor's existing approval boundaries. This skill does not override TRIAGE-001, ACCESS-01, code owners, release governance, or customer data permissions.

1. Name one bounded requirement, give it an ID, and choose the author-maintained mandatory check(s). A worker's account of its own work is not evidence.
2. Work on a synthetic or approved isolated copy. Inspect code topology first. Prefer Graphify's official `graphifyy` CLI in code-only local mode after provenance, version pinning and license review. Do not silently connect to hosted Graphify or index customer, child, employer or personal data.
3. Run only registered checks under a disposable least-privileged runtime. Capture a before/after project digest, command, exit status and bounded output. An unapproved command is never generated by a language model and executed.
4. Treat missing, stale, failing, crashed, timed-out, mutating, or changed-contract evidence as HOLD. Never treat Jev or any other model's confidence or a worker's claim as proof.
5. Use optional Jev only after explicit API key and R0-cost authorization. It can suggest allowlisted diagnostics, but it cannot authorize completion, payment, deployment or external communication. Model unavailability is a stop, not a pass.
6. Separately request independent review, security, privacy, licensing and founder-gated product release approval. Even all mandatory checks passing does not set `release_authorized` true.
7. Measure false completion, actual task acceptance, time to verified fix, token cost, cash cost, rework and settled revenue. Do not report 1,000x or sales without evidence.

Quick local demonstration:

```bash
python3 -B -m unittest discover -s tests -v
python3 -B harness.py run --project fixture --contract contract.json --evidence /tmp/pryntor-evidence.json --claim 'All done'
```

The sample holds because requirement R2 fails. It must not auto-repair, spend, publish or contact customers.
