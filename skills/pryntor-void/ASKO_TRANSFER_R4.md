# Launch Desk R4 · Asko-method transfer / concept acceptance brief
**17 Oct 2026. DESIGN HOLD: founder rejected present R3 visual direction, although Node and browser smoke remain technically green. Do not overwrite the live beta because of this brief.**

## True user problem, not visual inspiration
A founder or release owner needs to know what prevents a responsible launch, record actionable evidence, ask the right follow-up question, and leave with a review record that is unambiguously self-assessed versus independently approved. Current interface has six checks, score and JSON export, but the citrine sculpture has zero relationship to those decisions. CSS animation doesn't solve that.

**Asko analogue:** Asko used its original illustrated guide Ari to answer *real local scan questions*. Asko's mascot moves *because it is part of guidance*; sample actions actually run. Launch Desk's next visual concept must serve the review in the same structural way while looking like its own product.

## Distinct original concepts to PROTOTYPE, not auto-select

### Territory A — The Evidence Room
**Mechanism:** a bespoke illustrated dossier of six tabs and a physical decision trail. Each tab corresponds to an actual gate; interacting with it opens that gate. Recording evidence creates a visible page annotation with its gate ID and non-sensitive summary; marking self-reviewed adds a clearly labeled review mark, **never a fake approval stamp**. The optional motion is page/tabs changing only after actual user actions. Export creates the exact structured summary reflected by the visual map.

**References translated:** curated editorial rhythm (Minimal Gallery), interaction clarity (Frida/Sol), Asko's use of artwork as navigation. No copied Asko character, palette or template.

### Territory B — The Release Imprint
**Mechanism:** original graphic proofing/printmaking language, live "evidence imprint" assembled from actual state. Missing supporting notes remain visibly unfilled; a fully self-reviewed set still reads **Independent sign-off pending**. Motion: mark-making after evidence is entered or a gate is opened, not ambient auto-rotate. Output is a print-like review receipt. No false certification.

**References translated:** HyperFrames scale, original institutional identity, Asko's product-first state-linked visual world. No Celo/HyperFrames assets.

### Territory C — Field Guide to Shipping
**Mechanism:** an original small human/editorial guide that interprets the *existing* gate description and missing notes, offers context-specific next actions (open gate, add a note, export) and is explicitly **deterministic, not AI**. It is not Ari in new colours and not a chatbot pretending to review security. Hand-authored illustration changes expression only when it helps communicate empty, incomplete or ready-for-independent-review states.

**References translated:** Asko's meaningful, accessible character interaction and Frida's quiet on-demand agent affordance. The original character and story must be unlike Asko's.

## Founder-facing proof required before any R4 deployment
For EACH of the three: a realistic iPhone 390px viewport and desktop 1440px viewport, one real interactive use case (not a hero-only aesthetic), a new original illustration/asset family, side-by-side reference attribution and proof of divergence. State how the concept improves completion/confidence without inventing user data; don't claim user testing exists.

Score against `skills/pryntor-design-radar/ASKO_REFERENCE_METHOD.md`, then present the actual preview to founder. Do not choose a direction merely for visual fashion.

## The first actual workflow acceptance scenario
User starts at zero; chooses example; selects Security & Privacy; types a synthetic evidence note; the relevant map/guide responds specifically to that note's **presence** without interpreting it as externally verified; visits Operations & Rollback; sees what is still missing; exports JSON with correct score, 6 gates, selfAssessed:true and independentApproval:false; reloads and finds local entries intact; clears and restores the baseline. No raw private note is sent to an external API or included in a public share URL.

**Technical acceptance:** Node app and built HTTP smoke; browser 320/360/390/768/1440, keyboard-only flows, reduced-motion, contrast and axe-core, no JS errors/overflow, false claims, trackers or unapproved Adobe paid media. External Adobe Fonts kit remains conditional; local system fallback must preserve layout. Critical flows should have actual test receipts, not just static selector tests.
